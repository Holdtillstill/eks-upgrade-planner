# Observability

## Recommendation

For Kubernetes, run:

- Prometheus and Grafana via `kube-prometheus-stack`.
- Loki for OTLP application logs, or for stdout/container logs when you also run
  a node log collector such as Grafana Alloy, Promtail, or Fluent Bit.
- Tempo for traces.
- OpenTelemetry Collector for OTLP ingest and fan-out.

The app emits Prometheus metrics directly from `/metrics`. It emits OTLP/HTTP
traces when `OTEL_EXPORTER_OTLP_ENDPOINT` is set. It writes structured JSON logs
to stdout/stderr, and emits logs to the OpenTelemetry Collector when
`OTEL_LOGS_EXPORTER=otlp` is configured. The included observability values cover
the OTLP log path; stdout-to-Loki requires adding a cluster log collector.

## Metrics

Route labels are normalized to avoid high cardinality:

- `/eks/:version-upgrade-guide`
- `/addons/:addon/eks-compatibility`
- `/assets/*`
- `/:design`
- `/spa-fallback`

Key metrics:

```promql
http_requests_total
http_request_duration_seconds_bucket
http_requests_in_flight
eks_upgrade_planner_build_info
process_resident_memory_bytes
nodejs_eventloop_lag_seconds
```

Useful queries:

```promql
sum(rate(http_requests_total[5m]))
sum(rate(http_requests_total{status_code=~"5.."}[5m]))
histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket[5m])))
histogram_quantile(0.95, sum by (le, route) (rate(http_request_duration_seconds_bucket[5m])))
topk(10, sum by (route) (rate(http_requests_total[10m])))
```

## Local Verification

Run the production server:

```bash
npm run build
PORT=8080 NODE_ENV=production npm start
```

Check endpoints:

```bash
curl -fsS http://127.0.0.1:8080/healthz
curl -fsS http://127.0.0.1:8080/readyz
curl -fsS http://127.0.0.1:8080/metrics | grep http_requests_total
curl -I http://127.0.0.1:8080/eks/1-35-upgrade-guide
```

Run the smoke script against an already running server:

```bash
npm run smoke:local
```

## Local Kubernetes Stack

Values for a kind/demo setup are in `deploy/observability`.

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo add grafana https://grafana.github.io/helm-charts
helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
helm repo update

kubectl create namespace observability --dry-run=client -o yaml | kubectl apply -f -

helm upgrade --install kube-prometheus-stack prometheus-community/kube-prometheus-stack \
  --namespace observability \
  -f deploy/observability/kube-prometheus-stack-values.yaml
helm upgrade --install loki grafana/loki \
  --namespace observability \
  -f deploy/observability/loki-values.yaml
helm upgrade --install tempo grafana/tempo \
  --namespace observability \
  -f deploy/observability/tempo-values.yaml
helm upgrade --install otel-collector open-telemetry/opentelemetry-collector \
  --namespace observability \
  -f deploy/observability/opentelemetry-collector-values.yaml
```

Then install the app chart with `serviceMonitor.enabled=true` and an OTLP
endpoint pointing at the collector. The chart also ships an `EKS Upgrade
Planner` dashboard ConfigMap for Grafana's dashboard sidecar.

## Logs and Traces

Every request log includes `requestId`, `traceId`, method, raw path, normalized
route, status code, and duration.

The included OpenTelemetry Collector values receive OTLP logs from the app and
export them to Loki. To use stdout/container log collection instead, install a
node-level collector such as Grafana Alloy, Promtail, or Fluent Bit and point it
at Loki; that collector is intentionally not bundled with this app chart.

For traces, configure:

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
OTEL_SERVICE_NAME=eks-upgrade-planner
```

For optional OTLP logs:

```bash
OTEL_LOGS_EXPORTER=otlp
```

In Grafana Explore, use Tempo and search for:

```text
service.name = eks-upgrade-planner
```

Use Loki to query JSON container logs by Kubernetes labels. If using OTLP logs,
query the labels generated by the Loki OTLP exporter.
